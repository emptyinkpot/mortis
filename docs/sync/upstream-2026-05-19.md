### Batch 2 - Runtime/Daemon Fixes

Handle daemon and runtime fixes manually. Relevant upstream commit groups include:

- `fix(daemon)`
- `feat(daemon)`
- `fix(execenv)`
- `fix(runtimes)`
- `feat(runtimes)`
- `test(runtimes)`

These overlap Mortis Builder/Tester/runtime routing code and need targeted tests.

### Batch 3 - Database Query And Migration Surface

Manual merge only:

- `server/pkg/db/queries/*.sql`
- generated database code
- migrations after the Mortis migration boundary

This area affects runtime contracts and must be validated with query generation and backend tests.

### Batch 4 - Frontend Product Features

Manual merge by product area:

- squads
- usage pages
- my-issues filters
- agents detail/task panels
- attachment preview
- onboarding v2
- GitHub integration UI

These touch `packages/core`, `packages/views`, and `apps/web` heavily and should be split into small PRs.

### Batch 5 - Desktop

Manual merge only:

- updater behavior
- desktop runtime pages
- attachment/member preview routes
- keyboard shortcuts

Desktop files conflict with Mortis changes and should be verified with desktop-specific checks.

## Decision

Mortis should track upstream, but the next step should not be a broad merge. Continue with small sync branches and one owner per batch. Keep `mortis/operator-runtime` as the canonical branch until a batch is validated and merged.
